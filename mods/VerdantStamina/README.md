# Verdant Stamina

Client HUD mod, alpha: `0.1.0-alpha.3`. Built for the inspected Windrose UE 5.6.1 client and UE4SS 4.0.0.

- Smooth stamina drain/regeneration, olive green and concentric rings. The primary stroke is 30% thicker than the previous 9px stroke; the second and third are derived automatically at one half and one third (11.7 / 5.85 / 3.9 logical pixels). The primary's outer diameter stays fixed; thickening grows inward.
- `surface_style = "paint"` applies the worn-paint surface selected by the user. `"hatch"` selects dry hatching; `"flat"` restores the plain fill. All three are packaged and can be switched with a config edit and reload. The grain remains stationary while clipping planes rotate, thinner rings use a lighter texture, and the feathered endpoint uses the mean pigment tone. Geometry, alpha coverage, green/yellow hues and the low-stamina orange transition are preserved.
- Below 30% total stamina, the fill smoothly warms from green through gold to orange, reaching full orange by 10%. Changes ease over time in both directions, including a sudden drop or regeneration. Thresholds and easing live in `Scripts/config.lua`.
- `ui_scale = 1` preserves overall HUD size. A separate multiplier is available for uniform scaling, but the current refinement changes stroke thickness only. The `primary_thickness` variable derives both outside strokes and the primary centerline while keeping the outer radius fixed. Regenerate masks when changing thickness.
- Base capacity is read from the live `CT_CharactersAttributes.Hero_MaxStamina` curve (150 on the verified installation). Green represents permanent progression/talents plus currently equipped items. Each regular bonus ring represents another base unit; all rings after the third use the third ring's thickness. There is no three-ring cap.
- A new green ring needs at least 10 stamina of extra maximum capacity. A smaller remainder is merged into the previous ring's represented capacity, preserving the entire pool without a tiny new sliver. This is a capacity threshold; the current draining fill still moves continuously down to zero. `new_ring_min_capacity` configures it.
- All timed Endurance and direct MaxStamina modifiers share one smaller yellow wheel to the left. Its full circle represents the entire temporary reserve, including foods such as Intoxicating Fruit's direct +160. Yellow drains before green, and refills according to Windrose's actual total; this mod does not turn a replenishable Windrose buff into a one-use Zelda mechanic.
- A character with only the original base gets a 15% larger primary wheel; the approved compact geometry is used after a permanent capacity upgrade. The yellow wheel stays separate from the green ring count.
- The source reader polls the local ASC's owned active-effect structs on the game thread, reads evaluated modifier magnitudes, stack counts and actual durations, and checks both Endurance and MaxStamina sums against their native totals. Infinite stat/equipment/talent modifiers stay green; timed modifiers contribute to yellow. Temporary Endurance is removed using the actual native piecewise formula, rather than a fixed per-point assumption. Unsupported operations or incomplete replicated effects retain the original HUD and retry, instead of guessing the split.
- `visual_test_mode = false` is normal play. The optional display-only test maps the actual stamina percentage onto three green rings plus one yellow wheel; it never changes real attributes. The user's live visual test passed and the mode was then disabled.
- The live widget's current/max getters supply the actual total, including whatever upgrades/buffs the game has applied. The mod does not write stamina, attributes, effects, saves, or server state.
- Exhaustion/critical warnings use real stamina immediately. The last partial arc moves continuously; it is not rounded to segments.
- Existing position, reveal opacity/scale and visibility are inherited from the original indicator.
- Canvas anchors, offsets, alignment, Z order and render pivot follow the stock image on every frame. World-projected movement and the position assigned after widget creation are tracked live. A late source-size change rebuilds the local ring center; ordinary movement does not allocate new widgets. Construction notifications wait for a nonzero source size.
- Ship/menu HUD reconstruction is handled by a class-specific `NotifyOnNewObject` subscription. New stamina widgets enter the existing game-thread loop immediately and bind as soon as their image and model are ready, without waiting for the one-second recovery scan. The subscription is reused across reloads/toggles; it does no UMG work inside the object constructor. The mod also rebinds replaced/reparented source images or detached overlay canvases and re-hides stock paint if native UI code resets it. Nested HUD widgets can report `IsInViewport=false` while visible, so that flag is not used to discard them.

## Install

Install the official [UE4SS 4.0.0](https://github.com/UE4SS-RE/RE-UE4SS/releases/tag/v4.0.0) in `Windrose/R5/Binaries/Win64`. In `ue4ss/UE4SS-settings.ini`, set `MajorVersion = 5` and `MinorVersion = 6` under `[EngineVersionOverride]`.

Extract the mod ZIP into `Windrose/R5/Binaries/Win64` so `ue4ss/Mods/VerdantStamina/Scripts/main.lua` exists. An empty `VerdantStamina/enabled.txt` enables it. Retain existing loader/mod settings if already installed.

F8 toggles the mod and restores the original paint when disabled. F9 requests a bounded diagnostic in `ue4ss/UE4SS.log`. F10 reloads the Lua modules, restoring and rebuilding the rings. Settings, including colors and smoothing, live in `Scripts/config.lua`; F10 applies edits without a game restart. The development installer updates `Scripts/reload.txt` last to request the same reload automatically.

The scheduler retains the alpha.2 game-thread design and invalidates UE4SS's separate compiled-module cache for this mod; the new app also clears its new source modules from `package.loaded`. Subsequent source updates can hot-reload without a game restart. The startup banner reports alpha.3. The rename requires installing the new mod while the game is closed and removing the old WindroseStamina folder first to avoid running both mods. `python mods/VerdantStamina/dev/check_runtime.py` checks the latest live renderer revision, geometry and verified native source accounting; installed file hashes alone do not establish which revision is running.

To remove only this mod, close the game and remove `ue4ss/Mods/VerdantStamina`. Remove loader files only if no other mod uses them.

## Development and verification

`python mods/VerdantStamina/dev/test_mod.py` runs the actual Lua 5.4 models and native-boundary contract harnesses with Lupa from `tools/python`; `python mods/VerdantStamina/dev/generate_assets.py` regenerates antialiased masks after changing geometry; `python mods/VerdantStamina/dev/preview.py` renders the split-source preview; `python mods/VerdantStamina/dev/build.py` builds the distribution ZIP. The archive contains our Lua code and procedural PNG masks, no extracted game assets or bundled executables. Offline harnesses do not substitute for live verification of the native effect getter/replication behavior.

The renderer uses continuously rotated intersecting UMG clipping planes over circular antialiased masks. It does not approximate circles with rotated rectangles. Masks include a logical-pixel coverage ramp and transparent guard band for smooth edges at HUD size. The moving hard cut is retracted underneath a separately feathered cap, so the visible angled end also has antialiasing. Main nominal diameter is 47 logical pixels, hole diameter 29, and gap 1.5. These values account for the game's render scale: the preceding 62px configuration appeared about 81px wide on the user's screenshot, while the original appeared 61px wide. `mods/VerdantStamina/dev/preview.py` produces the offline geometry/color preview, including the three-ring state.

`mods/VerdantStamina/dev/texture_study.py` generates a separate comparison board for palette/texture discussion. Those surface candidates are not included in the installed renderer.

The first renderer loaded and rendered in the user's running game; runtime verification of the visual revision is recorded under `research/`. The model/adapter suite covers frame-rate independence, capacity accounting, partial arcs, immediate exhaustion, reconstruction, restoration after failure, the persistent game-thread scheduler and both Lua module caches. Death/respawn, multiplayer and long sessions still need validation.

The scheduler registers one native `LoopInGameThreadAfterFrames` callback. Do not replace it with `LoopAsync -> ExecuteInGameThread`: that pattern caused a native crash in the initial development build, matching upstream reports about unsafe async Lua registry access. The installed corrected build uses no async timers.
